## A · 导航和反馈（约 2 分钟，无模型消耗）

1. 左侧进入“项目”，选择已有测试项目；页面应只有项目管理和“交接 / 文件 / 记忆 / 计划 / 历史”几个切换面板。
2. 进入“记忆”，应先显示已保存记录，点击“新增记忆”才展开输入。保存后应有明确成功提示；重新进入仍能看到记录。空输入无法保存是正常行为。
3. 切到聊天、任务：不应再塞入完整项目管理表单，应有紧凑项目选择和“管理项目”。已有消息的会话仍锁定项目，新建会话可切换。
4. 在任务页输入草稿，点击管理项目再回任务，草稿应保留。遇到失败时错误应可见且可关闭。

## B · 单文件任务与真实执行交接（约 5 分钟，一次模型任务）

1. 在专用临时目录创建 `app.js`，内容 `const answer = 1;`。创建一个新测试项目，进入“文件”关联该目录。请用新项目避免已有排队任务。
2. 任务页选择该项目，执行方式选“单文件修改”，文件名 `app.js`，目标“把 answer 从 1 改为 2，保留其余内容”。保存并运行项目队列；不需要自己写 JSON 提示。
3. 完成后预览修改。确认目标文件及原文/新文，点击 Apply，在系统确认框核对目录和文件名。文件应变为 2，JavaScript 语法检查应通过。语法通过不代表功能测试通过。
4. 点击“保存执行交接”，到项目页查看交接：应注明已应用的提案、来源任务、语法检查、尚未运行功能测试，而不是只保存模型的 JSON。
5. 关闭重开工作台，选择任务、载入已有提案，查看审计；Undo 后文件应恢复为 1。保存“回退交接”，项目交接应说明先前修改已经撤回，历史版本仍在。
6. 可选防护检查：重新生成提案后，先手工修改 app.js，再 Apply；应拒绝覆盖。项目交接期间另有修改时，保存执行交接也应提示版本冲突。
